## 二、只有诊断面板 / localStorage 才有的 7 项（设置页查不到）

存于 `localStorage['vf.tune.v2']`，只能在诊断面板拖滑块改。**普通用户在手机上永远碰不到。**

| 状态 | 字段 | 默认 | 用途 | 删了会怎样 | 位置 |
|---|---|---|---|---|---|
| ☑ | `mountBehind` | 1 | 向上多挂几张 | 固化后不可调；默认值保留即可 | `flow-tuning.ts` 接口 / FLOW_DEFAULTS / LIMITS / FLOW_TUNE_ROWS |
| ☑ | `mountAhead` | 2 | 向下多挂几张 | 同上 | 同上 |
| ☑ | `fastRate` | 1.2 px/ms | 甩动判定阈值 | **留**（实测是活的关键路径，见下） | `flow-tuning.ts` |
| ☑ | `fastSettleMs` | 200 | 甩动静默时长 | **留**（同上） | 同上 |
| ☑ | `resizeSettleMs` | 140 | resize 防抖 | **留**：改窗口时一次拖拽能连发几十个 resize，每个都 rebuild 会卡；与 720/2160 无关 | 同上 |
| ☒ | `fadeMs` | 280 | 淡入时长 | **已删**（1.3.24）：改成 CSS 里写死 `0.2s`（见下方定值表） | 已移除 |
| ☒ | `fastFadeMs` | 140 | 甩动时淡入 | **已删**（1.3.24）：实测命中 0 次，纯死规则 | 已移除 |

> 「720 底图 + 2160 粘性」上线后，这 5 项到底还有没有用？2026-11-14 在现网 1.3.23 实测（`pg2-test/throttle_probe.js` + `cold_queue.js` + `scrollend_probe.js`）：
>
> | 项 | 实测 |
> |---|---|
> | `fastFadeMs`（甩动时缩短淡入） | 快甩 28 帧、`.vf-instant` 占 86% 的帧，但期间 `vf-ok` 新增 **0 次** —— 甩动中根本没有图上屏，这条 CSS 规则从未生效 → 删除零影响 |
> | `fadeMs` | 只喂 CSS 变量，值固定 → 搬进 CSS，运行时少 2 次 `setProperty` |
> | `fastRate` / `fastSettleMs` | 快甩 7 屏（26.3 px/ms）、窗口进出 **10 张**，期间只发 **1 条** 2160、0 张上屏；10 条 2160 冷生成同时砸的对照实验：首条 2511ms、**末条 8589ms** → 删了节流，停手那张要等 6.7~8.6s（现在是 2673ms） |
> | `resizeSettleMs` | 与预览档无关，纯粹防抖，保留 |
> | 原生 `scrollend` 能否顶替 `fastSettleMs` | **不能**：滚轮每响一格它就发一次（8 格 = 8 次、PageDown 1 次、慢滚 4 格 = 4 次）。它回答「这一格滚完了」，不是「人停手了」；拿它当信号会在每格之间反复开关节流 = 没有节流 |

### 定值（1.3.24，2026-11-14 定稿）

| 参数 | 值 | 依据 |
|---|---|---|
| `FAST_RATE` | **1.2 px/ms** | 视口高 1152px → ≈ 一屏/秒。Android `ViewConfiguration`：fling 区间 0.05~8 px/ms，真人快滑 2~4；实测 0.28 不触发、26 触发，阈值 0.5~2 之间表现一致。「浪费边界」理论上是一屏÷2400ms≈0.48，取 1.2 是故意偏向「慢拖也逐步变清晰」 |
| `FAST_SETTLE_MS` | **200 ms** | 桌面滚轮连续滚动事件间隔 50~120ms，真停手 ≥250ms，200 卡中间；原生 `scrollend` 不可用（见上） |
| `RESIZE_SETTLE_MS` | **140 ms** | 防抖常规区间 100~250ms，取偏快一侧 |
| 淡入时长（CSS 固定） | **0.2 s** `ease-out` | Material 3 里「fade（内容浮现）」= duration-short4 200ms；M3 指出 300ms 是「还跟得上操作」的心理上限。底下已垫 720，换的是清晰度不是有无，取短档 |

> 删这 7 项时：`LIMITS`（9 条）、`FLOW_TUNE_ROWS`（9 条滑块）、`TuneRow` 接口、`assign()` 里的数值分支可一并删；
> 但 `FLOW_DEFAULTS` 里的**数值本身要留下**（搬成组件内常量），否则虚拟滚动没阈值可用。

**新发现（重要，影响"关掉是否真的看不到"）**

`localStorage['vf.tune.v2']` 的优先级**高于**设置项。实测：

```
干净浏览器                      → diag:false   ✅ 配置生效
localStorage 注入 {"debug":true} → diag:true    ⚠️ 覆盖掉配置
```

**含义**：如果你手机上曾用诊断面板拖过滑块，本地存了 `debug:true`，那配置改成 false 也不管用。
清法：在诊断面板点「恢复默认」（`resetTune` → `clearOverride`），或清掉站点数据。
这也说明第 3 批"删调试层"时，`localStorage` 覆盖机制要一起处理，否则会出现"设置关了但还显示"的鬼故事。
