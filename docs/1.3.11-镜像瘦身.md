# 1.3.11 — 镜像瘦身：1.22 GB → 929 MB

## 一、为什么每版都在变大

我们的 Dockerfile 一直是这个套路：

```dockerfile
FROM ffvz/pigallery2:上一版
RUN rm -rf /app/dist        # ← 这行是"假删"
COPY dist /app/dist
```

**`RUN rm` 只在新层里写一个 whiteout 标记，父层那份 dist 的字节仍然躺在镜像里。**
`docker history` 一看就明白（1.3.10）：

```
55 层，其中 7 层是 COPY dist，每层 35.1MB
35.1MB  COPY dist        ← 1.3.10（可见）
35.1MB  COPY dist        ← 1.3.9（已 whiteout，但仍占 35MB）
35.1MB  COPY dist        ← 1.3.8（同上）
35.1MB  COPY dist        ← 1.3.7
35.1MB  COPY dist        ← 1.3.6
35.1MB  COPY dist        ← 1.3.5
35.0MB  COPY dist        ← 1.3.2
```

**245 MB 的 dist，只有 35 MB 有用，剩下 210 MB 是纯幽灵。**
叠加上 1.3.9 又加了一份 → 1.19 GB 涨到 1.22 GB。

---

## 二、做法一：把基础镜像压扁一次（-289 MB）

`RUN rm` 治不了这个病，因为它只能"遮盖"不能"回收"。真正的解法是把镜像压成单层：

```bash
# 1) 起一次性容器，把 dist 和 sourcemap 删掉（dist 每次构建都会重新 COPY）
docker run --name flat_tmp --entrypoint sh ffvz/pigallery2:1.3.10 \
  -c 'rm -rf /app/dist; find /app/src -name "*.js.map" -delete'

# 2) 导出成 tar（导出的是"最终可见文件系统"，whiteout 的幽灵自然消失）
docker export flat_tmp -o /vol1/1000/docker/flat_base.tar

# 3) 重新 import，用 --change 把元数据补回来
docker import \
  -c 'ENV NODE_VERSION=22.22.0' ... \
  -c 'WORKDIR /app' \
  -c 'EXPOSE 80 443' \
  -c 'ENTRYPOINT ["/usr/local/bin/pg2-entrypoint"]' \
  -c 'HEALTHCHECK --interval=40s --timeout=30s --start-period=60s --retries=3 \
      CMD wget --quiet --tries=1 --no-check-certificate --spider http://127.0.0.1:80/heartbeat || exit 1' \
  /vol1/1000/docker/flat_base.tar ffvz/pigallery2:flat-1310
```

`docker import` 不继承任何元数据，所以 Env / Workdir / Expose / Entrypoint / **Healthcheck** 必须逐条补。
补完用 `docker inspect` 对过一遍，确认和原镜像的 `Config` 一致（healthcheck 的 interval 40s / timeout 30s /
start-period 60s / retries 3 都对上了，容器起来仍是 `healthy`）。

结果：

```
ffvz/pigallery2:flat-1310   925MB   1 层（原来是 55 层）
```

`/app` 也从 185 MB 降到 149 MB（去掉 35 MB dist + 1.1 MB sourcemap）。

## 三、做法二：语言包只留 zh / en（-30 MB）

`/app/dist` 里有 16 种语言，每种 2.2 MB（main bundle + polyfills + scripts + styles + assets），共 35 MB。

**为什么删了不会坏**：`Localizations.init()` 是这么干的 ——

```ts
const dirCont = fs.readdirSync(ProjectPath.FrontendFolder)
    .filter((f) => fs.statSync(...).isDirectory());
Config.Server.languages = dirCont.filter((d) => notLanguage.indexOf(d) === -1);
```

**启动时扫 `/app/dist` 下有哪些目录，目录名就是语言列表。** 所以删目录 = 语言列表自动收缩，
`locale(Config.Server.languages, 'en')` 匹配不到时就回退 `en`，不会 500。不用改一行代码、也不用动 config.json。

实测（1.3.11 容器）：

```
/zh/  → 200        /en/  → 200
/de/  → 200（Accept-Language 无匹配 → 回退 en 渲染）
Accept-Language: de-DE  → 200（回退路径正常）
```

现在 `dist` 只剩 `en`（兜底，必须留）+ `zh`，**4.3 MB**。

## 四、结果

| | 镜像 | 层数 | tar |
|---|---|---|---|
| 1.3.10 | 1.22 GB | 55 | 1.2 GB |
| **1.3.11** | **929 MB** | 2 | **903 MB** |

省 **296 MB（-24%）**，其中 210 MB 是幽灵 dist、30 MB 是多余语言包、1.1 MB 是 sourcemap。

```
929MB   ← ffvz/pigallery2:flat-1310（单层底座）
4.39MB  ← COPY dist（zh + en）
```

### ⚠️ 以后必须守一条规矩

**每一版都要 `FROM ffvz/pigallery2:flat-1310`，不要 `FROM` 上一版。**
否则又会一层层叠 dist，一个月后又回到 1.2 GB。

底座要改（比如换 Caddy、改 entrypoint）时，重新压扁一次就行 —— 但那是一次性动作，
改完把新底座打成新的 `flat-xxxx`，后续继续从它派生。

## 六、还能再砍 210 MB（需要你点头）

`dpkg` 里最大的几块，全都是 **Intel 硬件转码驱动链**：

| 包 | 大小 |
|---|---|
| `libllvm19` | 126 MB |
| `mesa-libgallium` | 41 MB |
| `libz3-4` | 27 MB |
| `intel-media-va-driver` | 18 MB |
| 合计 | **≈ 210 MB** |

删掉这组后镜像能到 **~720 MB**。代价：**失去 QSV 硬件加速转码**，ffmpeg 软件编码仍然可用
（只是转 4K 视频会慢很多）。你的库里有视频（`.mp4/.mov`），如果平时不看转码后的版本、
或者本来也没开硬件加速，删了就白赚 210 MB。

其余大头都不能动：`node_modules` 118 MB（typeorm 29 / @img 17 / fluent-ffmpeg 13）、
`/app/src` 31 MB（后端编译产物）、`caddy` 51 MB（HTTPS 反代）、ffmpeg 那套编解码库（软编必需）。
