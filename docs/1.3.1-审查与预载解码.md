## 二、改了什么

### 1. 预载完立刻解码（核心）

```ts
img.onload = (): void => {
  const finish = (): void => { item.decoded = true; done(); };
  // 预载完立刻解码。挂载时才解码的话，大图会有几十 ms 空窗。
  if (typeof img.decode === 'function') {
    img.decode().then(finish).catch(finish);
  } else {
    finish();
  }
};
```

`decode()` 把位图放进浏览器的解码缓存，**挂载任何新的 `<img>` 都直接命中**，不再现场解码。同时用 `prefetchImgs` 持有 Image 引用，让已解码位图在缓存里活得更久。

### 2. 占位缩略图预热

```ts
private warmThumb(item: FlowItem): void {
  if (item.thumbWarmed || !item.gridMedia.isPhoto()) return;
  item.thumbWarmed = true;
  const im = new Image();
  im.fetchPriority = 'low';
  im.src = this.thumbOf(item);          // 与 .vf-item 的 background-image 同一个 URL
  if (typeof im.decode === 'function') im.decode().catch(() => undefined);
}
```

- 预载队列里的每一项都会顺带预热占位图（几 KB，几乎瞬时）
- `updateWindow()` 里对**马上要挂载**的窗口内项也预热一次，等于"先备好底图再上屏"

### 3. 恢复极短淡入（现在安全了）

```css
.vf-item img { opacity: 0; transition: opacity 0.16s ease-out; }
```

之前 0.12s 淡入会露黑，是因为底下是纯黑；现在底下是缩略图，所以淡入变成"**糊 → 清**"的柔和过渡，观感更接近原生相册。

### 4. 比例纠正合并到一帧

`onImageLoad` 不再直接 `rebuild()`，而是写进 `pendingRatios`，由 rAF 统一 flush：一次滚动挂上 3 张图，也只重建 1 次，锚点补偿只算一次。

### 5. 失败可重试

`img.onerror` 里 `prefetched.delete(index)`，下次调度会重新排队。

## 三、量化：为什么"预载即解码"值得做

在同一页面里对同一张图测量 `decode()` 耗时（Edge，NAS 局域网，图 1228×2000 / 2.4MB）：

| 场景 | 耗时 |
|---|---|
| **已解码过**（新 `<img>` 命中解码缓存） | **0.3 ms** |
| **未解码**（数据在内存、位图没生成） | **16.3 ms** |

差 **54 倍**，而且解码耗时随像素数线性增长——6000×4000 的图会到一两百毫秒，正好是你感知到的"黑一下"。
