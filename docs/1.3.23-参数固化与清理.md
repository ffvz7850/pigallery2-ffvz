## 三、固化的常量总表（`flow-tuning.ts` 下半部分）

```ts
PREVIEW_EDGE     = 2160   // 临时预览档短边
PRE_GEN_COUNT    = 2      // 预热张数
PREVIEW_SIZES    = [2160]  // 只留一档（1080/1440 从上线到现在没被请求过）
MOUNT_BEHIND     = 1      // 向上多挂几张
MOUNT_AHEAD      = 2      // 向下多挂几张
FAST_RATE        = 1.2    // 甩动判定 px/ms
FAST_SETTLE_MS   = 200    // 甩动静默
RESIZE_SETTLE_MS = 140    // resize 防抖
FADE_MS          = 280    // 淡入
FAST_FADE_MS     = 140    // 甩动时淡入
```

改这些要重新构建，没有运行时入口 —— 这是有意的：它们从上线到现在一个都没被真正调过，
留着只会制造"改了好像没生效"的排查成本。

## 四、删掉的四块

**① 诊断面板（前端）**
HTML 面板 25 行 + CSS 115 行 + 字段 `diagOn/diagText/tuneRows/diagTimer` +
方法 `startDiag/refreshDiag/closeDiag/serverTimingOf/onTuneInput/onColorInput/onLowToggle/resetTune/tuneValue`。

**② localStorage 覆盖层（`vf.tune.v2`）**
`readOverride / writeOverride / clearOverride / LIMITS / TuneRow / FLOW_TUNE_ROWS`。
它只服务诊断面板，而且会造成"设置里关了、这台设备还开着"的幽灵问题 —— 删掉更安全。

**③ `Server-Timing` 响应头 + `?vfdebug`**
后端两处 `setHeader`，前端 `serverTimingOf`，以及 `readTuning` 里的 `?vfdebug` 判断（实测被 Angular 路由吃掉，从来没生效）。
`X-Pg2-Pregen` **保留** —— 它让服务端给交互请求留名额，是功能性头。

**④ 死掉的档位与字段**
后端 `SIZES` 从 `[1080,1440,2160]` 收成 `[2160]`；
`Preview` 接口从 5 个字段（buf/mime/w/h/dct/ms）收到 2 个（buf/mime），
顺带删掉每张图都要算一遍的 DCT 因子推算（实测 libvips 根本不走 DCT）。

**E. 另外修掉两处**
- `needBg` 的注释说"三种情况不挂"，其中"大图已铺满"1.3.21 就删了 → 改成两种
- `startPreGen` 注释里"开 2 路并发"→ 实际单路（上一版已修）

## 五、两个差点翻车的地方

**① `isOpen()` 差点被误删。**
静态审计脚本只 grep 了 `flow.`，而父组件写的是 `this.flow?.isOpen()`（可选链），漏掉了。
是 `tsc` 报错才抓住：

```
lightbox.gallery.component.ts(585,40): error TS2551:
  Property 'isOpen' does not exist on type 'VerticalFlowLightboxComponent'
```

**教训：审计脚本只能给候选，必须让编译器复核。**

**② 三个测试脚本靠 localStorage 注入，覆盖层一删全失效。**
`v1321_test` 跑出 3 项 FAIL（`nFull=1/3`），看着像回归，实际是"注入没生效 → 一直跑在有底图模式"。
改成调真实配置接口（`pg2-test/low_switch.js`：GET → 改一项 → PUT → **刷新页面** → 测完恢复原值）。
这也是为什么"关底图"那几项重跑后能过：`nFull=3/3`、等待 2870ms。

## 六、验证

| 项 | 结果 |
|---|---|
| `v1321_test`（不闪 / 去重） | **14/14**（测试容器 8286 + 现网 8282 双绿） |
| `v1322_test` 无底图 | **4/4**（预热 pregen=2、无重叠、滚 3 屏 163ms、命中） |
| `v1322_test` 有底图 | **3/3**（老行为不变，滚 3 屏 120ms） |
| 设置页 | 只剩 `竖图流 · 底图颜色` / `竖图流 · 加载 720 底图` |
| `/pgapi/settings` | Gallery 字段 18 → **15**，flow 只剩 2 个，无残留 |
| 旧 config.json 里的残留字段 | 启动正常、被忽略，下次保存设置时自动清掉 |
| 2160 落盘 | 0 |
| CPU（滑 8 屏，无底图） | 冷态 `peak 321%`（一次性）/ 热态 `peak 148%`、`avg 20%`，停手回 0 |

> CPU 那个 321% 值得说一句：它是"改配置后刷新页面 → 服务端缓存被清 → 首屏 4 张 100MP 图排队生成"
> 的一次性峰值，持续不到 1 秒；紧接着第二次跑（缓存温热）就是 148%。
> 不是 1.3.16 那种持续 334%。
