# 1.3.5 — 打底架构重构（文件铺满 / 位图封顶 / 打开即铺）

## 本轮拍板

- **位图封顶**：文件层不清理，解码位图必须封顶。
- **打底 8 张 + idle 铺满**：打开即铺向下 8 张，其余后台铺满整个目录。
- 其余按推荐：打底图 DOM 化、ratio 补齐、甩动跳过淡入。
- **上游零改动**，只动 `src/frontend/app/ui/gallery/lightbox/flow/` 下的 3 个文件。

## 核心分层（本次最关键的设计）

| 层 | 内容 | 策略 |
|---|---|---|
| 文件层 | 720p 缩略图，57~101 KB/张 | 打开即铺 8 张 + idle 铺满整个目录，**不主动清理**（交给 HTTP 缓存） |
| 位图层 | 解码后 RGBA，720×1080 ≈ 3 MB/张 | 只保住离锚点最近 **12 张**，按距离淘汰 |
| 显示层 | `.vf-bg` + `.vf-full` 两层 img | 打底常驻不撤，原图 `decode()` 完才淡入 |

为什么不能"全部解码"：344 张 ≈ 1 GB 解码位图，会撑爆浏览器解码预算并被强制回收，滚回来要重新解码 → 恰好制造出要避免的闪烁。**文件小 ≠ 解码后小**，"不清理"只能作用于文件层。

## 改动清单

### 1. 打底图 DOM 化

- HTML：`.vf-item` 里加 `<img class="vf-bg" [src]="thumbOf(w.item)">`，去掉 `[style.background-image]`；原图 img 加 `class="vf-full"`。
- CSS：`.vf-item img.vf-bg { opacity: 1; transition: none }` —— **必须写在 `.vf-ok` 之后**才压得过 `.vf-item img { opacity: 0 }`（1.3.2 视频海报踩过同款特异性坑）。
- TS：删 `bgOf()`，`thumbOf()` 改 public 供模板调用。
- 收益：打底变成一等 DOM 节点，`complete / naturalWidth / load / error` 可观测、可兜底；测试不再靠 CSS 正则反推 URL（之前被文件名里的括号坑过一次）。

### 2. 打开即铺 8 张 + idle 铺满 + 位图封顶

- `primeThumbs(start)`：`open()` 时把 `start-2 .. start+8` 标成 high priority 并立即发起。
- `scheduleIdleFill() / idleFillBatch()`：`requestIdleCallback`（timeout 400，无该 API 时 `setTimeout 48ms` 兜底）每批 8 张，从点击那张向两侧扩，`fetchPriority='low'`，只下载不常驻解码。
- `thumbWanted` 改成**只增不减的累积待办**（`refreshWanted` 不再整体覆盖赋值），否则每次滚动都会把 prime 和 idle 的成果清掉；完成后由 `startThumb` 自己移出待办。
- `holdThumb() / trimThumbs()`：按离 `anchorIdx` 的距离淘汰，保住最近 12 张；每次滚动重算锚点时会重新裁剪。
- `pumpThumb` 排序：high priority 优先，其次离锚点距离。

### 3. ratio 补齐 + 甩动跳过淡入

- 缩略图 `onload` 里用 `naturalWidth/Height` 补齐 `ratioFixed=false` 的项，滑动中不再 `rebuild()`，消除位置跳变。
- `setFastScrolling()`（速度 > 1.2 px/ms）：给 `.vf-root` 加 `vf-instant`，CSS 关掉 `.vf-full` / `.vf-poster` 的 transition；停下 260 ms 恢复，并把甩动期间攒下的比例纠正一次性刷掉。
- `scheduleRatioFlush()` 在甩动中推迟重排。

## 踩坑记录

1. 构建时 `shutil.rmtree('dist')` 被沙箱批量删除保护拦下（256 文件 > 阈值 50）→ 改成 `os.rename('dist', 'dist_prev_134')`，让 Angular 新建干净目录。
2. `prescroll_test.js` 原本 `querySelector('img')` 取第一个 img；DOM 化后第一个变成 `.vf-bg`，会全部误判 → 改成 `img:not(.vf-bg)`，**对 1.3.4 / 1.3.5 都兼容**。
3. `thumb_test.js` 的 URL 解析加了 CSS `background-image` 回退，才能跨版本做 A/B；同时新增 `domReadyAtMount` / `burstDomReady` 两个 DOM 层指标。
4. bundle 里 `background-image` 仍出现 10 次，是上游其他组件的 CSS，不是本组件残留（组件内已无 `bgOf`）。

## 已知限制

- idle 铺满会为整个目录发一遍 720p 请求（344 张约 20 秒、4 并发、低优先级）。超大目录若不想这样，目前没有开关，只能改 `primeThumbs` 关掉 `scheduleIdleFill()`。
- `KEEP_THUMB_DECODED = 12` / `PRIME_AHEAD = 8` 是固定常量，未随屏幕或内存动态调整。
- 720p 缩略图与原图若色调/gamma 不一致，淡入时可能看到轻微色偏；这一项还没在真实图库上截帧比对。
