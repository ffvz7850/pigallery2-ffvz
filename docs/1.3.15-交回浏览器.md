# 1.3.15 — 交回浏览器

> 结论先行：**预载是负收益，你说得对。** 删掉之后 `scriptMs −19%`、`taskMs −35%`，
> 而且同一 URL 从此不会下两遍（181 个 URL，重复 0）。

---

## 一、为什么删

1.3.14 之前我们自己做了一整套：`new Image()` 预载 → 落 `prefetchImgs` 保活 → `decode()` 预热 →
`abortStale()` 掐掉过期的 → `trimPrefetch()` 控制上限。看起来每一步都有道理，但它们全在**和浏览器抢**：

| 我们的动作 | 浏览器的代价 |
|---|---|
| 4 个并发预载原图 | 抢走带宽，当前屏真正要显示的那张排到后面 |
| `new Image()` + DOM `<img>` 两份 ImageResourceContent | 资源生命周期各自管理，解码位图不一定复用 |
| 保活 K 张已解码位图 | 一张 8000px 的图解码后几百 MB，直接把 720p 从解码缓存里挤出去 |
| `abortStale` 清 `src` | 60MB 下到一半作废，滑回来从头再下 |
| 720p 预加载 | 40KB 的图磁盘命中 16ms，预加载省不下什么，却多占一个并发池 |

把预载压到 0、并发压到 1 反而更快 —— 这本身就是最直接的证据：**浏览器有连接池、优先级、按内存压力淘汰的完整策略，比我们拍脑袋的队列准。**

---

## 二、删了什么

组件 `vertical-flow.lightbox.gallery.component.ts`：**1152 → 743 行（−35%）**
参数层 `flow-tuning.ts`：**300 → 171 行（−43%）**

删除清单：

- 原图预载：`wanted` / `inFlight` / `prefetchFailed` / `prefetchImgs` / `pump` / `startDownload` /
  `markDownloaded` / `trimPrefetch` / `abortStale` / `isReady` / `sortByDirection`
- 720p 预载：`thumbWanted` / `thumbInFlight` / `thumbFailed` / `pumpThumb` / `startThumb` / `addThumbWanted`
- 状态字段：`fetched` / `thumbWarmed` / `stage` / `thumbStage` / `stats` 计数
- 参数：`fullSlots` / `fullAhead` / `fullBehind` / `fullKeep` / `thumbSlots` / `thumbAhead` /
  `thumbMountAhead` / `thumbFastAhead`
- 设置项：7 个「竖图流 · …」数值项全部下掉

保留：虚拟滚动、窗口挂载、比例纠正、resize、顶栏、淡入、甩动判定、720p 底图（原生 `<img>`）、
底图颜色。**`.vf-bg` 不再预热** —— 挂载即由浏览器发请求，40KB 本地命中，实测挂载后 4/4 就绪。

## 三、底图颜色进设置

设置页（`/admin` → 基础分组，就在「Interface zoom 界面缩放」旁边）：

| 设置项 | 默认 | 说明 |
|---|---|---|
| 竖图流 · 底图颜色 | `#4e4636` | 十六进制色值，如 `#2b2b2b`（中性灰）、`#000000`（纯黑） |
| 竖图流 · 显示诊断条 | 关 | 等于地址栏加 `?vfdebug` |

竖图流内按 `?vfdebug` 还有**取色器**，拖一下立刻生效，不用保存、不用刷新：

```
底图颜色  [颜色块]  #4e4636
```

两者改的是同一个值（设置页全局、取色器本机），优先级：

```
内置默认 → Config.Gallery.flowVoidColor → localStorage['vf.tune.v2']
```

实测：设置页填 `#2b2b2b` → 保存 → 刷新后仍是 `#2b2b2b` → 灯箱底色 `rgb(43,43,43)` → 改回 `#4e4636` 复原。
取色器改成 `#1b2a3a` 也是即时生效。

## 四、实测

### 性能（同一时段、同目录、4× CPU 降速）

| | 1.3.14（有预载） | **1.3.15（无预载）** | 变化 |
|---|---|---|---|
| `scriptMs` | 639 / 583 | **519 / 516** | **−19%** |
| `taskMs` | 1844 / 1787 | **1146 / 1302** | **−35%** |
| 帧间隔 p95 | 20.4 / 22.3 ms | 19.8 / 20.6 ms | 略好 |
| longTask | 0 | 0 | — |
| 重复请求 | 偶发（abort 后重下） | **181 URL / 0 重复** | 归零 |

### 功能

| 项 | 结果 |
|---|---|
| 调参层 `v1315_test.js` | **14/14** |
| 720p 挂载后就绪 | 4/4，滚动 5 屏每屏 5/5 |
| 原图上屏 | 4/4 |
| 顶栏 | ALL-PASS |
| resize | 0.68 → 0.68 → 0.68 |
| 打底 | 13/13、ratio 100% |
| 设置页颜色 | 改 `#2b2b2b` → 保存 → 下发 → 灯箱生效 → 改回 |

### 已知限制

**大图仍会「闪一下加载」** —— 单张 8000px 解码要 1 秒以上，浏览器内存/解码预算是硬约束，这一版不再试图用 JS 绕过。
现在能做的是让这一下尽量短、底色尽量柔和，而不是假装它不存在。
